# Proposed research evidence preservation gate (Z1)

Failure mode: a local test pass and a linked issue were reported without preserving the reproducible evidence in the repository. The author conflated artifact preservation with production admission. These are separate gates.

For future experiments, before claiming a preserved baseline or starting a blind challenge:
1. Assign experiment ID and canonical parent issue; establish the authorized public/private boundary and review content before any repository write. Never expose credentials, private Gmail, PII, restricted documents or blinded answers to reviewers before freeze. When public visibility is incompatible with blindness or privacy, preserve original bytes in an authorized restricted store and publish only approved sanitized metadata or a digest receipt. A public draft is public.
2. Freeze exact inputs, implementation, test commands and raw output, reference-label provenance, artifact manifest, environment and limitations. Pin original bytes and SHA-256 independently of mutable working files. Keep source originals distinct from annotated notes.
3. Create a dedicated draft PR or authorized restricted evidence record before declaring preservation complete. Put inspectable files and unchanged archive in the review package; label candidate scope and AUTHORITY_EFFECT=NONE. Do not merge or grant authority.
4. Run the byte-integrity gate. Verify archive digest, every extracted file and manifest coverage. Negative tests must fail closed on absent or altered data. Local integrity is not proof of remote delivery.
5. Read back the exact remote commit, PR metadata, changed paths, archived blob and file hashes; record timestamp, PR URL, head SHA and result. Only then report PRESERVED_DRAFT. If any required evidence or readback is absent, report LOCAL_ONLY or PRESERVATION_HOLD and list the blocker; do not claim completion. Hash receipts are not authenticated evaluator identities.
6. Freeze independent reviewer ledgers before sharing answer keys; retain each receipt and raw result separately. Challenge against pinned code and input. Preserve original and correction in different commits/paths, rerun the exact challenge, report regressions and unresolved discrepancies. No self-admission or formal ACAT score.
7. Carry these status fields in every research handoff: LOCAL_INTEGRITY, REPOSITORY_READBACK, INDEPENDENT_REVIEW, ADMISSION. Missing is HOLD, never PASS. Preserve null results.

The included offline verifier is a case-specific implementation of the byte-integrity portion, not a general security scanner or a remote attestation service. A matching mutable receipt alone is not sufficient; reviewers compare against the independently recorded original digest and immutable commit. Proposed durable integration: reuse the existing evidence graph, ACAT-R and issue intake contracts; require the preservation receipt at the research handoff gate and consider a scoped CI check after independent review and human ratification. This draft does not alter protected branch rules, repository-wide policy or CI.
