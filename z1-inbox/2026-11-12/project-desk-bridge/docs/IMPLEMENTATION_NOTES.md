## Parts
- engine/intent-bridge.cjs (Test B): compare two INTENT-OS workspace revisions; three-way plan against the latest RECONCILED snapshot kept in `desk.imports`; human choices ADOPT / KEEP_DESK / RECORD_ONLY; deterministic `brg-` proposal ids; idempotent re-import; stale-write rejection returns the caller's choices; one-case round-trip is a review preview only; decision dependencies are gate tasks + `depends`. Identity anchor: task `source == "<case>/<task>"` AND project origin names the case.
- engine/core.cjs: history-prefix verification (append-only; only oldest-event roll-off at the 5000 cap).
- engine/evidence-adapter.cjs (Test A): works only on human-approved, structured extraction records, never raw mail. Scope = thread + explicit message ids + purposes. Public ids are keyed HMAC (salt is a local secret). Email text is untrusted quoted data. All proposals inert (effect NONE, human review required). Corroborate/challenge against Desk and INTENT-OS records.
- engine/resource-events.cjs: hash-chained event log: discovery, acquisition, charge, payment, settlement, use, remaining-capacity observation, yield, waste, benefit. Exact 6-decimal integer arithmetic. Units pinned to ratified RESOURCE_UNITS.yaml snapshot (operations 52aa7c0e); money units are local candidates until Z2 registers them. Receipts prove transactions only; benefit requires outcome evidence. Maps to the existing ledger CLI only for registered units; executes nothing.
- bin/desk-bridge.cjs: offline CLI; never overwrites inputs; private output 0600; no network module.
Repairs after audit 1 (F1-F5) and audit 2: see audit/AUDIT_LOG.md. In short: capped-history roll-off is refused unless the human passes --accept-roll-off and is always reported; saved import snapshots count as history; quantities are exact micro-units capped at 1e9 with a log-wide bound; the resource log header is in the hash chain and every read/append verifies it; a DONE Desk task is never proof of submission; email freshness is timestamp-based and same-day is unorderable; new tasks adopted from INTENT-OS obey the saveTask gates (own note per DONE task); duplicates for the same origin/source become RECORD_ONLY; reserved JavaScript names are refused; a transaction reference (any evidence type; letter case and surrounding spaces ignored, punctuation significant) backs one payment and one charge; after audits 3 and 4, messages are fixed text (Desk refusal reasons are reduced to a fixed class) and non-tool error text is hidden unless --show-details; link-decision reports dropped events like apply; the evidence adapter verifies the resource log and ignores corrected payments.

Independent of INTENT-OS: reads exported JSON only; no writeback.
