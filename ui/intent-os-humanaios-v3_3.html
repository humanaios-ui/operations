Intent-OS

Pipeline — this project's steps, in delivery order

Like a project board, with one extra rule: a step only turns green when it's verified, not when someone says it's done.
done = verified complete in progress = built, awaiting verification waiting = needs a decision first

Metrics — what the work must actually move

Like a metrics dashboard, with one difference: projections are marked as projections and never counted as results.

Solid bar = measured today. Dashed edge = projected after the staged work — not counted. Gold tick = target. Only measurements taken after work is verified count.

Decisions — calls only the project owner can make

Like an approvals queue. Work that needs one of these shows red in the pipeline until it's decided. A tap is not a ratification; the hash is.

How projects run here — the six stages every project walks

Like a project lifecycle framework, except each stage has a checkable condition instead of a description.

A project is fully set up once every stage's condition has been true at least once. The pipeline above is one project on this map; the project data section below is where a new project fills it in.

Four planes and four rules — what holds no matter the score

Like the separation between a permissions system, an audit log, a forecast, and a report card — kept apart so none can rewrite another.

Every judgment about behavior must be written as a check a machine can run — not "was it careful?" but "unauthorized actions = 0", "claims without support = 0", "stated confidence vs. actual accuracy". If a judgment can't be written that way, it isn't scored yet.

Deadlines — moves that die on a date

Like calendar deadlines — only things with a real closing window belong here.

Commitments — predictions made before seeing results

Rare in any product: you write down what you expect, how confident you are, and when you'll know — before the result exists. Over time this shows whether the team's judgment is getting better.

Verified records — the receipts this board rests on

Like an audit log: each entry is a fingerprint (checksum) of a real file, so anyone can later confirm nothing was quietly changed.

Project data — the whole board as one editable file

Everything above renders from this. Edit and apply to reshape the board; export saves it with every checkbox and decision; import picks up exactly where a board was left.
