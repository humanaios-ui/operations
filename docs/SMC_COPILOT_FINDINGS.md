## Findings

Each finding cites the supporting metric(s) and states a falsifier observation.

### F-SMC-01 — High dangling reference rate across executable and workflow units

**Observation.** A large fraction of units reference store paths that do not resolve inside the repository.  
**Metric.** `per_population_metrics.tools_py.dangling_rate = 0.7818`; `workflows.dangling_rate = 0.5429`; `root_md.dangling_rate = 0.5205`; top dangling targets include `{TOOL_NAME}_{ts}.json` (22), `nonexistent/path/that/cannot/exist.json` (13), and multiple `acat_*_session*.py` names with unit counts 9–10.  
**Structural failure.** Shared-memory graph contains many edges to non-existent stores, weakening reproducibility and CI trust in path contracts.  
**Falsifier.** Observation that the majority of top dangling targets resolve under an alternate root (sibling repository, generated artifact directory outside git, or runtime mount) that the census basename/relative walk cannot see.

### F-SMC-02 — Spine attachment is partial; workflows and agents_skills largely unattached

**Observation.** Only a minority of units reference the designated spine documents (`REGISTERED.md`, `GOVERNANCE.md`, `SESSION_RITUALS.md`, `CURRENT.md`). Workflows and agents_skills show near-zero attachment.  
**Metric.** `tools_py.spine_attachment = 0.2182`; `docs.spine_attachment = 0.3495`; `workflows.spine_attachment = 0.0571`; `agents_skills.spine_attachment = 0.0`; `root_md.spine_attachment = 0.2329`. Top shared stores still rank the four spine files highest by unit count.  
**Structural failure.** Operational automation (workflows, agent skills) is not mechanically tethered to the governance spine, increasing drift risk between live process and ratified memory.  
**Falsifier.** Discovery of indirect spine consumption (e.g., workflow calls a tool that itself always loads REGISTERED.md) that reference-grep on the workflow file cannot surface.

### F-SMC-03 — Isolation remains material in docs and agents_skills

**Observation.** Substantial populations reference no shared store at all.  
**Metric.** `docs.isolation_rate = 0.3301`; `agents_skills.isolation_rate = 1.0`; `workflows.isolation_rate = 0.2857`.  
**Structural failure.** Isolated units form private memory islands; their outputs or assumptions are invisible to the shared graph and cannot participate in cross-unit consistency checks.  
**Falsifier.** Evidence that isolated units publish to stores under names outside the mechanical extraction patterns (e.g., environment variables, database keys, or binary formats) that the census regex does not treat as artifact filenames.

### F-SMC-04 — Hash chaining and content-addressing are rare

**Observation.** Few units mention sha256 or previous-hash chaining.  
**Metric.** Across populations, `sha256_users` totals 21 (12 + 7 + 0 + 0 + 2); `chain_users` totals 1 (only in tools_py).  
**Structural failure.** Shared stores lack widespread content-addressed integrity links, so “same path” does not imply “same bytes” across sessions or satellites.  
**Falsifier.** Observation that integrity is enforced outside the repo (CI artifact digests, external object store ETags) such that in-repo sha256/chain references are unnecessary.

### F-SMC-05 — Session-shaped and template stores appear in the shared layer

**Observation.** Paths with session/transient shape and explicit non-existent templates rank among top shared and top dangling stores.  
**Metric.** Top shared includes `{TOOL_NAME}_{ts}.json` (22 units); shared tier distribution includes L0=21; top dangling repeats the same template and session-named modules.  
**Structural failure.** Durable shared-memory slots are occupied by names that encode session or placeholder semantics, mixing L0 working memory into the long-term reference graph.  
**Falsifier.** Evidence that those names are only documentation examples and that no runtime unit ever writes or reads a file under the literal template string (i.e., the reference-grep overcounts pedagogical citations).

### F-SMC-06 — agents_skills population is minimal and fully isolated

**Observation.** Only two files under `.agents/skills/**`; both isolated from shared stores.  
**Metric.** `agents_skills.unit_count = 2`; `isolation_rate = 1.0`; `spine_attachment = 0.0`.  
**Structural failure.** Agent-skill surface is not yet integrated into the shared-memory mesh that tools and root governance docs use, creating a parallel capability path without census visibility.  
**Falsifier.** Observation that agent skills are deliberately thin wrappers whose real references live in a different tree (e.g., `.claude/skills` or external skill registry) that this census population definition excludes by design.

## Notes on method limits (not findings)

- Extraction is mechanical (quoted paths + inline names ending in store extensions). Dynamic path construction, environment variables, and non-text stores are invisible.
- Existence checks use exact relative path then basename walk; case or multi-root ambiguity can produce false dangling.
- Tier labels are heuristic (spine names → L3/L2; session markers → L0; else degree-based). They support structural discussion only.
